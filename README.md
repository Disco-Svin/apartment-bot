# Бот-мониторинг квартир (Минск)

Проверяет каждые 15 минут шесть площадок объявлений о продаже квартир
в Минске и шлёт в Telegram новые объявления, подходящие под фильтр:
2+ комнаты, цена до $100 000 (или эквивалент в других валютах на
конкретной площадке). Умеет также присылать несколько получателям и
отдельно следить за изменением цены у конкретных объявлений (см. ниже).

Источники:
- **Kufar** (`re.kufar.by`) — через внутренний JSON API площадки
- **Onliner** (`r.onliner.by`) — через внутренний JSON API площадки
- **Realt.by** — парсинг данных, встроенных в HTML страницы поиска
- **Domovita.by** — парсинг данных, встроенных в HTML страницы поиска
- **GoHome.by** — парсинг HTML-карточек страницы поиска
- **Твоя Столица** (`t-s.by`) — парсинг HTML-карточек страницы поиска

Официальных публичных API у этих сайтов нет — используются те же запросы,
что делает сама страница поиска в браузере. Если площадка изменит
внутреннюю структуру сайта, соответствующий модуль в `sources/` может
сломаться и потребует правки — в первую очередь стоит проверять
`sources/realt.py`, `sources/domovita.py`, `sources/gohome.py` и
`sources/t_s.py` (они парсят HTML, а не стабильный API).

Проверялись также **hata.by** и **weekend.by** — не подключены: у обеих
маленький объём объявлений по нужному фильтру и не получилось найти
надёжный способ отсечь города-спутники Минска (Фаниполь и т.п.) от
самого Минска. Можно добавить позже, если понадобится.

Стоит иметь в виду: одна и та же квартира от одного и того же агентства
нередко публикуется сразу на нескольких площадках (это обычная практика
рынка недвижимости, не баг бота) — так что иногда возможны уведомления
об одной и той же квартире с разных источников.

## Как это устроено

- `sources/*.py` — по одному модулю на площадку, у каждого есть функция
  `fetch(...)`, возвращающая список объявлений в едином формате (`Listing`).
- `storage.py` — хранит ID уже отправленных объявлений в `data/seen.json`,
  чтобы не слать одно и то же дважды.
- `notifier.py` — отправка сообщения в Telegram через Bot API.
- `main.py` — один прогон: собрать объявления со всех площадок → отфильтровать
  → сравнить с уже виденными → отправить новые → сохранить состояние.
- `loop.py` — обёртка над `main.py` для непрерывной локальной работы
  (бесконечный цикл со сном между прогонами).
- `config.yaml` — все настраиваемые параметры (город зашит как Минск
  внутри каждого модуля-источника, остальное — в конфиге).

При **первом** запуске бот не шлёт уведомления по всем найденным
объявлениям (иначе в чат сразу прилетит сотня старых) — он просто
запоминает текущий срез как "уже видели". Уведомления начнутся со
второго прогона, когда появится что-то новое.

## Важная особенность realt.by и domovita.by

В отличие от Kufar и Onliner, у этих двух сайтов не получилось найти
рабочую серверную сортировку "сначала новые" и (для realt.by) рабочую
пагинацию — сайты всегда отдают примерно один и тот же срез объявлений,
который бот дальше фильтрует и сортирует сам. Это значит, что покрытие
по этим двум площадкам — best-effort: подавляющее большинство новых
объявлений будет поймано, но теоретически возможны редкие пропуски при
очень высокой активности на сайте. Kufar и Onliner работают через
настоящий API с сортировкой по дате и являются основным, надёжным
источником.

## Установка

1. Установите Python 3.10+ и зависимости:
   ```
   pip install -r requirements.txt
   ```

2. Создайте Telegram-бота: напишите в Telegram **@BotFather**, отправьте
   `/newbot`, следуйте инструкциям — получите токен вида
   `123456789:AA...`.

3. Узнайте chat_id каждого получателя: пусть каждый напишет
   **@userinfobot** любое сообщение — бот пришлёт в ответ числовой ID.
   Это чат, куда будут приходить уведомления (важно: каждый получатель
   должен также написать вашему боту `/start` один раз, иначе бот не
   сможет писать ему первым). Несколько получателей — не проблема,
   ID перечисляются через запятую.

4. Скопируйте `.env.example` в `.env` и впишите туда токен и chat_id(ы):
   ```
   copy .env.example .env
   ```

5. Проверьте, что всё работает, одним прогоном:
   ```
   python main.py
   ```
   Первый запуск ничего не пришлёт в Telegram (это ожидаемо — см. выше
   про bootstrap), но в консоли должно быть видно строку вида
   `fetched=... filtered=... new=... notify=0 bootstrap=[...]`.

6. Настройте фильтры под себя в `config.yaml` при необходимости —
   комментарии в файле объясняют каждый параметр.

## Запуск на своём компьютере (локально)

Вариант A — простой бесконечный процесс:
```
python loop.py
```
Оставьте окно (или запустите как фоновую задачу, например через
`pythonw loop.py` — без консольного окна).

Вариант B — через Планировщик заданий Windows (надёжнее — если процесс
упадёт, следующий запуск всё равно произойдёт по расписанию):
1. Планировщик заданий → Создать задачу
2. Триггер: повторять каждые 15 минут, бессрочно
3. Действие: запустить программу
   - Программа: путь к `python.exe` (тот, куда установлены зависимости)
   - Аргументы: `main.py`
   - Рабочая папка: папка проекта (`d:\WORK\БОТ КВАРТИРА`)

## Запуск бесплатно на GitHub Actions

Если готовы завести GitHub-репозиторий — это способ держать бота
работающим без своего сервера и без своего постоянно включённого
компьютера, полностью бесплатно (в публичном репозитории Actions
не лимитирован).

1. Создайте репозиторий на GitHub и запушьте туда этот проект
   (файл `.github/workflows/poll.yml` уже готов).
2. В настройках репозитория: **Settings → Secrets and variables →
   Actions → New repository secret** — добавьте `TELEGRAM_BOT_TOKEN`
   и `TELEGRAM_CHAT_IDS` (значения из вашего `.env`, сам `.env` в
   репозиторий не попадёт — он в `.gitignore`).
3. Workflow запускается по расписанию каждые ~15 минут (GitHub иногда
   задерживает запуск на несколько минут при нагрузке — это ограничение
   платформы, повлиять на него нельзя). Можно также запустить вручную
   во вкладке **Actions → Poll apartment listings → Run workflow**.
4. Каждый прогон коммитит обновлённый `data/seen.json` обратно в
   репозиторий — так состояние "что уже отправляли" сохраняется между
   запусками.

## Отслеживание изменения цены конкретных объявлений

Отдельно от общего поиска можно следить за ценой у конкретных, вручную
выбранных объявлений — например, если вы уже присмотрели квартиру и
хотите узнать, если продавец скинет цену.

1. Добавьте прямые ссылки на объявления в `watchlist.yaml`:
   ```yaml
   urls:
     - https://re.kufar.by/vi/1080143434
     - https://r.onliner.by/pk/apartments/1280360
   ```
2. При каждом прогоне (`main.py`/`loop.py`/GitHub Actions) бот сверяет
   текущую цену с последней известной и, если она изменилась (в любую
   сторону), присылает отдельное уведомление с разницей. Состояние —
   в `data/watchlist_state.json`, коммитится так же, как `seen.json`.

Работает для объявлений с Kufar, Onliner, Realt.by и Domovita.by —
у GoHome.by и Твоей Столицы нет отдельной страницы объявления с
надёжным способом её опознать, для watchlist они пока не поддержаны.

## Разовая рассылка "что добавлено сегодня"

`today_digest.py` — присылает в Telegram все подходящие под фильтр
объявления, добавленные сегодня (по времени Минска), не трогая
основное состояние дедупликации (`data/seen.json`) — можно запускать
сколько угодно раз без риска что-то пропустить или задублировать в
обычной рассылке:
```
python today_digest.py
```
Учитывает только Kufar, Onliner, Realt.by и Domovita.by — у GoHome.by
и Твоей Столицы в выдаче нет даты создания объявления, только дата
обновления, так что "сегодняшние" среди них определить не получится.

## Проверка отдельных источников

`test_sources.py` — вспомогательный скрипт, запускает все `fetch()`
напрямую и печатает результат в консоль, без отправки в Telegram и без
учёта уже виденных объявлений. Удобно для проверки, что площадка не
сломалась:
```
python test_sources.py
```
